# SherpaHR · Project Desk

Приложение для работы с проектами, задачами и обсуждениями.
Новое тестовое: **[task_v7.md](task_v7.md)** — развитие существующего продукта.

## Запуск

Нужны Docker Engine с Compose v2 и свободный порт 8097:

```bash
docker compose up --build -d --wait
```

Откройте **http://localhost:8097**. Первый запуск скачивает зависимости и собирает
интерфейс. Последующие запуски используют образ и сохраняют данные в volume.
Другой порт: `PORT=8099 docker compose up --build -d --wait`.

```bash
docker compose logs app
docker compose exec -T app php backend/tests/smoke.php
docker compose exec -T app php backend/tests/attention.php
docker compose down
```

Тесты создают собственную временную БД и сервер; ваши рабочие данные не меняются.
Добавление комментариев реализовано. Smoke-тест проверяет запись, автора,
валидацию, границы доступа и архив; отдельный тест внимания проверяет причины,
порядок задач, текстовые сигналы и границы сроков с фиксированным временем.
Чтобы заново создать только демонстрационные данные этого Compose-проекта:
`docker compose down --volumes`, затем повторите запуск. Удаление volume стирает
локальные изменения в задачах и комментариях.

## Приложение

- В боковом меню — доступные проекты; в проекте — задачи с поиском и фильтром статуса.
- Стартовый обзор руководителя объединяет незавершённые задачи всех исполнителей
  в его активных проектах. Есть фильтры проекта и причины, поиск и ручное обновление.
  У каждой задачи показаны причины внимания и цитата из обсуждения, если она есть.
- В карточке можно менять задачу, исполнителя, статус и срок, читать обсуждение.
  Можно добавить комментарий и сразу продолжить разбор. После записи обзор обновляется.
- Архивные проекты доступны для чтения.
- Переключатель демо-пользователя позволяет посмотреть приложение от разных лиц.
  Это демонстрация прав, **не настоящая аутентификация**; приложение предназначено
  для локальной работы. Compose публикует порт только на loopback.
- Все имена и данные вымышлены. Даты в UTC, сроки создаются относительно первого
  запуска БД и затем сохраняются; приложение не передвигает их при перезапуске.

Техническая справка: [разработка](docs/development.md),
[API](docs/api.md), [контекст продукта](docs/product.md).

### Как проверить основной сценарий

1. Оставьте демо-пользователя Анну и откройте «Требует внимания».
2. Сравните задачи разных проектов: у них видны причины и текст обсуждения.
3. Найдите задачу «Определить владельца справочника». Она требует вмешательства,
   хотя не заблокирована и не имеет срока; текстовый сигнал и отсутствие исполнителя
   позволяют не потерять её среди обычных задач.
4. Откройте карточку, прочитайте всю переписку, назначьте участника проекта и
   отправьте комментарий. Комментарий сохраняется от имени выбранного пользователя.
5. Переведите задачу в «Готово»: она исчезнет из обзора, оставаясь в проекте.
6. Переключитесь на Бориса: он видит задачи доступных ему проектов, но обзор
   руководителя пуст, поскольку активных проектов под его руководством нет.
7. Откройте архив: задачи и обсуждения доступны только для чтения.

### Границы обзора

Порядок внимания: блокировка, возможная просьба о помощи, просрочка,
отсутствие исполнителя, срок в ближайшие 48 часов. При равном приоритете
сначала идут более ранние сроки, затем ID. Это выбранная продуктовая политика,
а не обязательная последовательность из исходного задания.

Текстовые признаки определяются локальной эвристикой фраз в описании и
комментариях. Возможны пропуски и уже неактуальные просьбы. Поэтому интерфейс
называет сигнал возможным, показывает источник и позволяет прочитать всю переписку.
Ответ руководителя сам по себе не снимает сигнал; завершение задачи исключает её
из обзора. Формального процесса эскалации и внешней модели анализа текста нет.

Время и сроки показываются в UTC. Данные демонстрационные, вход заменён выбором
пользователя. При большом объёме задач следующий шаг — серверная пагинация обзора;
в этой версии список ограничен доступными активными проектами, но не разбит на страницы.

## Работа с агентом и сдача

Кандидат самостоятельно выбирает агента, модель, редактор и инструменты.
Сессия или токен организатора не требуются. Порядок журнала и сдачи:
[AGENTS.md](AGENTS.md), [скил отчётности](.agents/skills/sherpa-hr-task-lifecycle/SKILL.md).

Одна центральная issue в `SherpaRPA/SherpaHR` содержит журнал каждого промпта
и действия агента. Решение — в отдельной ветке публичного форка кандидата,
PR открывается внутри этого форка. При сдаче обязательны итоговый отчёт,
проверенный head SHA и комментарий с `@fxpw`. Issue закрывается как сданная
на проверку; PR остаётся открытым.

Если используете чужой код или публичные решения, укажите источник,
условия использования и собственные изменения.

Если для решения нужны новые пути за пределами приложения, добавьте их
в `.gitignore` в секцию `CANDIDATE SOLUTION` перед
защитными исключениями. Секреты и персональные данные не публикуйте.
